## 五、维护规范

1. **发现即记录** — 任何新问题立即新增条目
2. **修复后更新** — 更新状态、填写修复 commit、新增 test_case
3. **提交前必查** — 每次 git commit 前检查此清单是否需要更新
4. **无 SKIP 原则** — 框架限制不得跳过，必须修复（字体度量差异 B-018/S-001 除外：已记录暂缓，待字体引擎统一优化时处理）
5. **CSS 标准铁律** — 框架 fallback 必须使用 CSS 标准默认值
6. **字体尺寸例外** — fontSize/font-family 等字体渲染差异标记为"渲染限制"，记录后在问题清单标记为"暂不修复"，优先处理框架布局/样式等真正的 CSS 标准偏差
