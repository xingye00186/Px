## 三、框架需要做的准备（按优先级）

### P0：包格式标准（最关键基础设施）

**当前状态**：ComponentRegistry 支持 `component-libraries` 目录扫描，但没有包级元数据。

**需要建设**：

```yaml
# px-package.yml — 社区包标准格式
name: px-data-table
version: 1.2.0
description: High-performance virtualized data table
author: community-dev
license: MIT

# 组件声明（编译期消费）
components:
  px-data-table: ./components/DataTable.vue
  px-table-column: ./components/TableColumn.vue
  px-table-pagination: ./components/TablePagination.vue

# 依赖
requires:
  px-framework: ">=0.9.0"
  px-widgets: ">=1.0.0"

# 主题 Token（可选）
theme-tokens:
  --table-header-bg: "#f5f7fa"
  --table-row-hover: "#ecf5ff"
  --table-border-color: "#ebeef5"

# 平台插件（可选，移动端后）
platform-plugins:
  android: ./android/
  ios: ./ios/
```

**框架侧改造**：ComponentRegistry 扩展 `loadPackage()` 方法，读取 `px-package.yml`，自动注册组件 + 解析依赖。

---

### P1：设计 Token + 主题注入

**当前状态**：vc-ui 组件样式硬编码在 `<style>` 中（如 `.btn-primary { background: #409EFF }`），无法被应用覆盖。

**需要建设**：

```vue
<!-- 社区组件使用 CSS 变量（而非硬编码颜色） -->
<template>
  <div :class="'btn btn-primary'">{{ text }}</div>
</template>

<style>
.btn-primary {
  background: var(--px-primary-color, #409EFF);
  color: var(--px-primary-text, #FFFFFF);
  border-radius: var(--px-border-radius, 4px);
}
</style>
```

```php
// 应用层注入主题
ThemeProvider::register('my-theme', [
    '--px-primary-color' => '#FF6B00',
    '--px-border-radius' => '8px',
]);
```

**依赖**：CSS C2.5-full（var() 运行时支持）完成后自然就绪。

---

### P2：Slots 完善（组件可组合性的基础）

**当前状态**：Modal.vue 用 `{{ footerSlot }}` 字符串属性模拟插槽，不是真正的 `<slot>`。

**需要建设**：Vue 3 标准 Slots（默认 slot / 命名 slot / scoped slot）——这是社区组件可组合的前提。

```vue
<!-- 社区 Modal 组件 -->
<template>
  <div class="modal">
    <div class="modal-header">
      <slot name="header">{{ title }}</slot>
    </div>
    <div class="modal-body">
      <slot><!-- 默认内容 --></slot>
    </div>
    <div class="modal-footer">
      <slot name="footer">
        <px-button @tap="onClose">关闭</px-button>
      </slot>
    </div>
  </div>
</template>
```

## 四、对照总结：Px 社区生态的差距与优先建设

| 优先级 | 建设项 | 当前状态 | 对标 | 工作量 |
|---|---|---|---|---|
| **P0** | `px-package.yml` 包格式标准 | 无（ComponentRegistry 有基础） | pubspec.yaml / package.json | 1-2 周 |
| **P0** | Slots（组件可组合性） | 无（字符串模拟） | Vue 3 `<slot>` | 2-3 周 |
| **P1** | 设计 Token + CSS var() 主题 | C2.5-full 后就绪 | Flutter ThemeData | 1 周（框架侧） |
| **P1** | `px` CLI 工具 | build.bat 手工脚本 | flutter CLI / create-vue | 2-3 周 |
| **P2** | 社区包注册表 | 无 | pub.dev / npm | 4-8 周 |
| **P2** | 测试工具包 | 框架内部有，社区不可用 | flutter_test / @vue/test-utils | 2-3 周 |
| **P2** | CONTRIBUTING.md + RFC 流程 | 无 | 所有成熟框架 | 1 周 |
| **P3** | Platform Channel（插件系统） | 无 | Flutter MethodChannel | 移动端 Phase 4 同步 |
| **P3** | DevTools 扩展 API | DevTools 存在但无扩展接口 | Vue DevTools Plugin | 3-4 周 |
| **P3** | API 文档生成器 | 无 | api.flutter.dev | 2-3 周 |

## 五、核心判断

1. **Px 的社区基础比想象中好**——`ComponentRegistry` 已具备自动扫描 + 前缀命名 + 冲突检测；`library/vc-ui/` 已有 60 个组件原型。缺的不是"从零建设"，而是"标准化 + 暴露接口"。

2. **包格式标准（`px-package.yml`）是第一优先级**——没有标准包格式，社区无法分发、无法声明依赖、无法自动发现。这是 pub.dev / npm 的等价物，是生态的地基。

3. **Slots 是组件可组合性的前提**——没有 Slots，社区组件只能是"独立控件"，无法构建"容器+内容"的复合组件（如 DataTable 的列定义、Tabs 的标签页内容）。

4. **设计 Token 是主题生态的基础**——Flutter 有 `ThemeExtension`，Vue 有 CSS 变量，React 有 Context + CSS-in-JS。Px 应该用 CSS var()（C2.5-full 后自然就绪）+ `ThemeProvider::register()` 注入。

5. **不要过早建设包注册表**——Flutter 的 pub.dev 是在框架稳定后才建的。先用 Git submodule / 本地目录分发社区包（ComponentRegistry 已支持），等社区包数量 >20 后再建注册表。

6. **对标 Flutter 而非 npm**——Px 的社区生态应该更像 Flutter（Widget 库 + Platform Channel 插件 + pub.dev 评分），而非 npm（海量低质量包）。质量管控靠**组件快照测试 + AOT 兼容性验证**（`px validate`），而非靠人工审核。
