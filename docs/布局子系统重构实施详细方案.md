首批重构目标：覆盖了最核心的“样式访问统一”、“接口收敛”、“算法拆分”和“解析器合并”，能够快速消除技术债务并为后续优化铺路。下面给出详细实施方案。

---

## 整体策略

- **严格执行“每阶段独立提交”**，每完成一个阶段即运行全量单元测试 + 快照比对，确保无回归。
- **第一阶段必须最先完成**（因为后续阶段都依赖统一的 `ComputedStyle` 访问）。
- **第二、三阶段可并行**，但建议先二后三（接口收敛后，拆分的 Flex 能更干净地使用新接口）。
- **第七阶段可最后进行**，它不依赖前三个阶段，但可放在最后以减少合并冲突。

## 第一阶段：消除 `getStyleArray()` 双轨制

### 1.1 为 `ComputedStyle` 补全缺失的布局属性
当前 `ComputedStyle` 已有很多属性，但缺少 Flex/Grid 专用字段。需新增：
```php
public readonly float $flexGrow;
public readonly float $flexShrink;
public readonly string $flexBasis; // "auto" 或 "0" 或 "100px"
public readonly int $order;
public readonly string $alignSelf; // "auto", "stretch", ...
public readonly string $justifySelf;
```
在构造函数中从 `$declarations` 解析这些值，并设置默认值（与 CSS 规范一致）。

### 1.2 改造所有策略中的 `getStyleArray()` 调用
**全局搜索** `->getStyleArray()`，在以下文件中替换：

- `FlexLayoutStrategy.php`
- `GridLayoutStrategy.php`
- `BlockLayoutStrategy.php`（虽然后者已较少使用，但也要改）
- `AbsolutePositioning.php`
- `VNodeRenderer.php`（它在 `renderNodeToElement` 中使用了 `getStyleArray`，需改为 `$node->computedStyle` 直接访问）

**替换模式示例**（以 Flex 为例）：
```php
// 旧代码
$grow = (float)($ch->getStyleArray()['flexGrow'] ?? 0);
$shrink = (float)($ch->getStyleArray()['flexShrink'] ?? 1);
$basis = $ch->getStyleArray()['flexBasis'] ?? 'auto';

// 新代码（使用 computedStyle）
$style = $ch->computedStyle;
$grow = $style?->flexGrow ?? 0.0;
$shrink = $style?->flexShrink ?? 1.0;
$basis = $style?->flexBasis ?? 'auto';
```

对于 `width`、`height` 等长度属性，直接使用 `$style->width->toPx()` 或 `$style->resolveWidth($containerW)`。

### 1.3 删除 `RenderNode::getStyleArray()` 和 `$_styleCache`
- 移除 `RenderNode::$styleCache` 及相关方法。
- 移除 `clearStyleCache()`（不再需要）。
- 修改 `VNodeRenderer` 和 `LayoutResolver` 中所有对 `getStyleArray` 的调用。

### 1.4 验证
- 运行 `phpunit` 中所有布局相关测试（尤其是 Flex/Grid 用例）。
- 对比重构前后的 `engine_layout.json` 快照，差异应为零。

## 第二阶段：统一布局策略接口（移除 `@deprecated` 存根）

### 2.1 删除各策略类中的旧 `resolve()` 方法
这些方法散落在：
- `BlockLayoutStrategy`
- `InlineLayoutStrategy`
- `TableLayoutStrategy`
- `MultiColumnLayoutStrategy`
- （`FlexLayoutStrategy` 和 `GridLayoutStrategy` 已无旧方法，但需检查）

对于 `InlineLayoutStrategy` 和 `TableLayoutStrategy`，它们目前实现了 `resolveWithBuilder`，但旧 `resolve` 还在内部构造 `LayoutConstraints`。直接删除 `resolve`，并确保 `LayoutResolver` 只调用 `resolveWithBuilder`。

### 2.2 修改 `LayoutResolver::resolveNodeInternal`
确保所有分支都使用 `resolveWithBuilder`，不再有条件分支调用旧方法。

### 2.3 清理接口定义
将 `LayoutStrategyInterface` 中仅保留 `resolveWithBuilder` 方法，移除 `resolve` 的声明。

### 2.4 验证
- 检查 `LayoutResolver` 中所有策略调用点，确保不存在 `->resolve(` 调用。
- 运行全量测试，确保无 “undefined method” 错误。

## 第三阶段：拆分 `FlexLayoutStrategy` 巨类

### 3.1 新建内部 DTO 类（放在 `Px\Rendering\Layout\Flex` 命名空间）
- `FlexItem`：包含 `node`, `flexGrow`, `flexShrink`, `flexBasis`, `order`, `mainSize`, `crossSize`, `margin` 等。
- `FlexLine`：包含 `items`, `totalMain`, `maxCross` 等。

### 3.2 提取三个纯函数类
**`FlexItemCollector`**（静态方法 `collect(RenderNode $container, ComputedStyle $style): FlexItem[]`）
- 遍历 `$container->children`，提取每个子项的 flex 属性、计算基准尺寸（`flex-basis` → 初始 mainSize）。
- 返回 `FlexItem[]`。

**`FlexLineBreaker`**（静态方法 `breakLines(FlexItem[] $items, LayoutConstraints $constraints, bool $wrap): FlexLine[]`）
- 根据 `flex-wrap` 和容器 main-axis 尺寸，将 items 分成多行。
- 处理 `gap`。

**`FlexDistributor`**（静态方法 `distribute(FlexLine $line, LayoutConstraints $constraints, array $flexStyles): void`）
- 对单行执行 `flex-grow` / `flex-shrink` 分配。
- 应用 `justify-content` 和 `align-items`。
- 修改 `FlexItem::mainSize` 和 `crossSize`，并设置 `x/y` 偏移。

### 3.3 重构 `FlexLayoutStrategy::resolveWithBuilder`
```php
public function resolveWithBuilder(...) {
    $items = FlexItemCollector::collect($node, $style);
    $lines = FlexLineBreaker::breakLines($items, $constraints, $wrap);
    foreach ($lines as $line) {
        FlexDistributor::distribute($line, $constraints, $style);
    }
    // 将 FlexItem 的位置写回 RenderNode，并构建 LayoutFragment
    $builder->replaceChildren($this->itemsToFragments($items));
}
```

### 3.4 验证
- 运行 Flex 专项测试，确保所有用例（wrap、grow、shrink、align、justify）结果不变。
- 对比快照差异。

## 第七阶段：合并解析器职责（CssMappings / CssValueParser / StyleResolver）

### 7.1 将解析函数集中到 `CssValueParser`
- 将 `CssMappings::parseHexColor`、`parsePixels`、`parseFlex`、`parseFontWeight`、`parseTextAlign`、`parseBorder`、`parseOpacity`、`parseIdent`、`parseBackgroundImage`、`parseTransform`、`parseBoxShadow` 全部迁移至 `CssValueParser` 作为静态方法（同名）。
- 保留 `CssMappings` 仅包含 `PROPERTY_MAP` 和 `INLINE_PROPERTY_MAP` 常量。

### 7.2 修改 `StyleResolver` 作为唯一门面
- 删除 `StyleResolver::parseInlineStyle` 中的重复解析逻辑，改为调用 `CssValueParser` 的方法。
- 让 `StyleResolver` 对外提供 `resolve()` 和 `parseInlineStyle()`，内部组合使用 `CssValueParser`。
- 删除 `CssMappings` 中的 `dispatchParser` 和 `parseInlineStyle`（改为调用 `StyleResolver`）。

### 7.3 更新所有外部调用点
- 全局搜索 `CssMappings::parse*`（如 `CssMappings::parseHexColor`），替换为 `CssValueParser::parse*`。
- 搜索 `CssMappings::parseInlineStyle`，替换为 `StyleResolver::parseInlineStyle`。

### 7.4 删除冗余代码
- 移除 `CssMappings::getPropertyMap()` 和 `getInlinePropertyMap()` 等，直接用常量。
- 移除 `CssStyleHelper` 中对旧 `CssMappings` 的依赖（如果存在）。

### 7.5 验证
- 运行样式解析单元测试，确保所有颜色、长度、变换等解析结果不变。
- 运行端到端布局测试，确保样式渲染一致。

## 阶段依赖与执行顺序

```
第一阶段（样式统一）→ 第二阶段（接口收敛）→ 第三阶段（Flex拆分）
                                     ↓
第七阶段（解析合并）← 可并行于二、三之后（也可最后执行）
```

> **建议执行顺序**：1 → 2 → 3 → 7  
> 因为第二阶段移除旧 `resolve` 后，第三阶段拆分 Flex 时能更专注于新接口。
