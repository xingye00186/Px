## 2026-06-17 会话

### 1. 浏览器参考数据导出 — dump_layout.js 集成

**背景**：`46595c5` 中的 `dump_layout.js` 是浏览器端 JS 脚本，通过 `getBoundingClientRect()` + `getComputedStyle()` 提取元素位置和计算样式。下午的架构升级（`ef2ac9f` 创建 PxTest Pipeline）时，`EdgeDomStrategy` 直接使用 `--dump-dom` 输出原始 HTML，丢失了 `dump_layout.js` 的注入步骤。

**修改文件**：
- `tools/PxTest/Pipeline/Strategy/PipelineSteps.php` — `buildCssTestWrapper()` 在 `</body>` 前注入 `<textarea id="layout-output">` + `dump_layout.js`
- `tools/PxTest/Pipeline/Strategy/BrowserRefStrategy.php` — `EdgeDomStrategy` 从 `--dump-dom` 输出中提取 textarea JSON，保存为 `browser_ref_level_0.json`

**数据流**：
```
BrowserRefStep
  ├─ buildCssTestWrapper() → 注入 CSS 基线 + <textarea> + dump_layout.js
  └─ EdgeDomStrategy
       └─ Edge headless --dump-dom
            ├─ JS 执行：遍历 DOM，getBoundingClientRect/getComputedStyle
            ├─ JSON 写入 <textarea id="layout-output">
            └─ PHP 提取 textarea 内容 → browser_ref_level_0.json
```

### 2. 引擎 ↔ 浏览器格式对齐

**决策**：引擎数据向浏览器格式看齐（浏览器是黄金标杆）。引擎树通过 `LayoutNormalizer` 转成扁平 `{viewport, elements: [{tag, x, y, w, h, depth, styles, text}]}`。

**修改文件**：
- `tools/PxTest/Layout/LayoutNormalizer.php` — **新建**，引擎树→浏览器格式规范器（35+ 样式键名映射、颜色值格式化）
- `tools/PxTest/Pipeline/Strategy/PipelineSteps.php` — `LayoutDumpStep` 保存 `engine_ref_level_0.json` + 注入 context
- `tools/PxTest/Pipeline/ElementCompareStep.php` — 重写，直接对比同格式 `engine_ref` vs `browser_ref`

**格式映射表**：

| 维度 | 引擎原始 → 归一化 |
|------|------------------|
| 结构 | 树 `{type, children[]}` → 扁平 `{elements: [{tag, x, y, w, h, depth}]}` |
| 样式键 | `fontFamily` / `bg` / `borderBottomWidth` → `font-size` / `background-color` / `border-bottom-width` |
| 颜色值 | `3022366`（整数）→ `rgb(255,0,255)`（CSS 字符串）|
| 文本 | `content` → `text` |
| 类型 | `type`（div/span/text）→ `tag`（div/span/p） |

### 3. 对比输出分类

**决策**：差异分为四类，终端和报告文件均按此输出：

| 分类 | 含义 | 行动 |
|------|------|------|
| MISSING | 浏览器有但引擎没导出 | 优先增强引擎属性导出 |
| GEOMETRY | 位置/尺寸偏差 | 修正引擎布局计算 |
| MISMATCH | 两边都有但值不同 | 修正格式/计算差异 |
| STRUCTURE | 元素数量/tag 映射错误 | 对齐元素映射 |

**修改文件**：
- `tools/PxTest/Pipeline/ElementCompareStep.php` — 分类输出 + 汇总统计

### 5. 截图控制权统一收口

**问题**：`Application::handleDumpArgs()` 在 `--dump-layout` 和 `--dump-layout-after-frames` 中私自截图，导致 `MultiFrameStep` 每次调用 exe 产一张 timestamp 截图。32 case × 多次迭代 = 169 张垃圾截图（~10MB）。

**根因**：`framework/Core/Application.php` 中 `handleDumpArgs()` 设计耦合——dump-layout 职责是导出布局 JSON，却附带截图副作用。

**修复方案**：截图只由 `main.php` 中的 `--screenshot=xxx` 路径触发，从 `Application::handleDumpArgs()` 中移除截图代码。

**修改文件**：
- `framework/Core/Application.php` — 移除两处截图耦合代码（-12 行）
- `tools/PxTest/Pipeline/Strategy/DumpStrategy.php` — 去掉 `--no-screenshot`
- `tools/PxTest/Pipeline/MultiFrameStep.php` — 去掉刚加的 `--no-screenshot`

**截图控制链**（修复后）：
```
--skip-screenshot → ScreenshotStep 不加入 pipeline，0 张
无 --skip-screenshot → ScreenshotStep 每个 case 用 --screenshot=xxx 产 2 张
其他所有步骤（dump_layout/multiframe/browser_ref）不产截图
```

### 8. 锚点自定义属性 + 内容子树提取 + 坐标归一化

**问题**：引擎渲染含 app 外壳（85 元素），浏览器仅测试内容（9 元素），按全局索引对比不对齐。锚点靠颜色/尺寸识别，不够确定。

### 10. 引擎 CSS 继承属性缺失修复（LayoutNormalizer 默认值补全）

**问题**：引擎的 `serializeRenderNode()` 只导出节点上显式设置的样式。CSS 继承属性（`font-weight`、`opacity`、`text-align` 等）在子节点上无显式设置则不导出，导致 23 个 MISSING。

**修复**：在 `LayoutNormalizer::normalizeNode()` 中补全 CSS 默认值（`font-weight:400`、`font-style:normal`、`text-align:start`、`opacity:1` 等 9 个属性）。

**效果**：MISSING 185 → 162（-23）

**修改文件**：
- `tools/PxTest/Layout/LayoutNormalizer.php` — 追加 CSS 默认值补全逻辑

**引擎层根因**：`framework/Core/Application.php` 中 `serializeRenderNode()` 应在序列化前递归传播 `color`、`fontSize`、`lineHeight` 等继承属性。入口 `dumpLayoutToFile()` 已定位，添加 `propagateInheritedStyles()` 方法即可再消约 60+ MISSING。

## 2026-06-19~21 会话（case-007 修复 + 虚线边框 + auto-margin 重构）

### 1. FlexLayoutStrategy 两阶段重布局修复

**问题**：case-007 flex-wrap 布局中三个卡片（bx-item）间距丢失、容器被撑宽、卡片高度错误。

**根因**：
- `flex-wrap` 容器被子项 auto-width 撑宽（缺乏 `!$hasExplicitW` 守卫）
- 主轴定位用 `w`/`h`（content box）而非 `visualW`/`visualH`（border box），padding 导致坐标偏移
- two-pass 中 `h=0` 重置未排除 scroll container，导致 UI 空白

**修改文件**：
- `FlexLayoutStrategy.php` — 3 处修复（auto-width skip、visualW/visualH 定位、scroll container guard）

### 2. Phase G 容器溢出检测

**问题**：case-007 右侧溢出未被检测。

**根因**：Phase G 边界计算未包含 padding/border 偏移，且未过滤绝对定位元素。

**修改文件**：
- `ElementCompareStep.php` — `scanContainerOverflow()` 加入 padding/border 边界、跳过 absolute/fixed

### 3. Phase L 布局断言（测试补强）

**问题**：平面对比不能捕获容器溢出等结构性缺陷。

**新增**：`LayoutValidationStep.php`，三项断言：
- A：flex-wrap 容器宽度 ≤ 父内容区宽度
- B：flex item 间距等于指定 gap（visualW 之间）
- C：block 子项未被 cross-axis stretch 过度撑高（跳过 scroll container）

**注册**：`PipelineBuilder.php` — 在 dump_layout 后加入 Phase L

### 4. 噪声消除——源头统一策略

**问题**：line-height 因子值（1.6）→ 浏览器 px 值（22.4px）格式差异、border-color 引擎单色 vs 浏览器四色、font metric 差异产生 ~130 diff。

**修复**：
- `LayoutNormalizer.php` — line-height 在引擎 JSON 中即转为 px（乘 fontSize）；border-color 构造为 DOM 格式 `rgb R G B`
- `ElementCompareStep.php` — 扩展 `$ENGINE_DEFAULT_ONLY_KEYS`/`$BROWSER_DEFAULT_SKIP_KEYS`

### 5. 三项根治改进（序列化层）

**问题**：引擎序列化与浏览器格式不对齐。

**修复**：
- #1：`Application.php` 移除 `$styleKeys` 中 per-side border 键（`borderTopWidth` 等），与 `borderWidth` 简写重复
- #2：`Application.php` serializeRenderNode 递归传递 `$parentStyle`，补全 `textAlign` 继承
- #3：`CssValueParser.php` + `CssMappings.php` 识别 `linear-gradient` 设置 `bgFromGradient`，`LayoutNormalizer` 据此跳过 `background-color` 导出

### 6. ExeDiscovery 路径修复

**问题**：`--force-build` 编译后的新 exe 在项目根目录，但 `findExe` 不查该路径。复制到 `bin/` 失败时旧 exe 永不被替换。

**修改**：`ExeDiscovery.php` — 添加项目根目录为最高优先级候选路径

### 7. `* { box-sizing: border-box; }` 全局选择器支持

**问题**：浏览器 HTML 有 `* { box-sizing: border-box; }`，引擎不解析全局选择器，导致 padding 撑宽盒子溢出。

**修复**：
- `CssMappings.php` — `parseStyleBlock()` 增加 `*`/`html`/`body` 选择器解析
- `RenderTreeManager.php` — `resolveNodeStyle()` 区分 `*`（全元素）和 `html`/`body`（仅对应类型节点）
- `App.vue` — 加入 `<style>` 块含全局重置 CSS

### 8. 虚线/点线/双线边框渲染

**问题**：`border-style: dashed/dotted/double` 被 CssMappings 正确解析但从未被渲染层读取——VNodeRenderer 不传递、GdiRenderContext 只用 `fillRect` 画实线。

**修复链**：
- `VNodeRenderer.php` — 读取 `borderStyle` 传入元素数据
- `GdiRenderContext.php` — 新增 `drawBorderLine()` 方法（dashed/dotted/double/solid）；圆角+非 solid 边框走 drawBorderLine 路径（直角，但样式正确）
- `Application.php` — `borderStyle` 加入导出列表
- `LayoutNormalizer.php` — 映射 `borderStyle` → `border-style`
- `ElementCompareStep.php` — `border-style` 加入 `$BROWSER_DEFAULT_SKIP_KEYS`

### 9. auto-margin 浏览器机制对齐重构

**问题**：`_marginAutoApplied` / `_marginAutoOffsetX` 是补偿性书签字段，掩盖了"两阶段重布局不触发 auto-margin 重算"的根本缺陷。

**重构**：
1. 移除 `_marginAutoApplied` 标志位（2 处 BlockLayoutStrategy + 1 处 FlexLayoutStrategy）
2. `resolveNormalFlow()` 设置 x 后清零 `_marginAutoOffsetX`
3. children 循环无条件执行 auto-margin（`_marginAutoOffsetX` 撤销/重做处理首次布局偏移）
4. 最终方案：flex-grow > 0 的 item 在 Step 1 标记 `_deferAutoMargin=true`，BlockLayoutStrategy 跳过 auto-margin；two-pass 清除标记后自然触发计算

**最终机制**（与浏览器一致）：
```
浏览器:  flex-grow 分配 → 容器尺寸确定 → auto-margin 计算（1 次）
引擎(前): first-pass（错误宽度计算 auto-margin）→ flex-grow → two-pass（撤销再重算）
引擎(后): first-pass（跳过 auto-margin）→ flex-grow → two-pass（用正确宽度计算，1 次）
```

**修改文件**：
- `BlockLayoutStrategy.php` — 移除 `_marginAutoApplied`、加 `_deferAutoMargin` 守卫、`resolveNormalFlow` 加清零
- `FlexLayoutStrategy.php` — Step 1 加 `_deferAutoMargin` 标记、two-pass 清除标记
