# 迭代备忘录

> CSS 标准对齐测试迭代记录

## 2026-06-17 会话

### 1. 浏览器参考数据导出 — dump_layout.js 集成

**背景**：`46595c5` 中的 `dump_layout.js` 是浏览器端 JS 脚本，通过 `getBoundingClientRect()` + `getComputedStyle()` 提取元素位置和计算样式。下午的架构升级（`ef2ac9f` 创建 PxTest Pipeline）时，`EdgeDomStrategy` 直接使用 `--dump-dom` 输出原始 HTML，丢失了 `dump_layout.js` 的注入步骤。

**修改文件**：
- `tools/PxTest/Pipeline/Strategy/PipelineSteps.php` — `buildCssTestWrapper()` 在 `</body>` 前注入 `<textarea id="layout-output">` + `dump_layout.js`
- `tools/PxTest/Pipeline/Strategy/BrowserRefStrategy.php` — `EdgeDomStrategy` 从 `--dump-dom` 输出中提取 textarea JSON，保存为 `browser_ref_level_0.json`

**数据流**：
```
BrowserRefStep
  ├─ buildCssTestWrapper() → 注入 CSS 基线 + <textarea> + dump_layout.js
  └─ EdgeDomStrategy
       └─ Edge headless --dump-dom
            ├─ JS 执行：遍历 DOM，getBoundingClientRect/getComputedStyle
            ├─ JSON 写入 <textarea id="layout-output">
            └─ PHP 提取 textarea 内容 → browser_ref_level_0.json
```

### 2. 引擎 ↔ 浏览器格式对齐

**决策**：引擎数据向浏览器格式看齐（浏览器是黄金标杆）。引擎树通过 `LayoutNormalizer` 转成扁平 `{viewport, elements: [{tag, x, y, w, h, depth, styles, text}]}`。

**修改文件**：
- `tools/PxTest/Layout/LayoutNormalizer.php` — **新建**，引擎树→浏览器格式规范器（35+ 样式键名映射、颜色值格式化）
- `tools/PxTest/Pipeline/Strategy/PipelineSteps.php` — `LayoutDumpStep` 保存 `engine_ref_level_0.json` + 注入 context
- `tools/PxTest/Pipeline/ElementCompareStep.php` — 重写，直接对比同格式 `engine_ref` vs `browser_ref`

**格式映射表**：

| 维度 | 引擎原始 → 归一化 |
|------|------------------|
| 结构 | 树 `{type, children[]}` → 扁平 `{elements: [{tag, x, y, w, h, depth}]}` |
| 样式键 | `fontFamily` / `bg` / `borderBottomWidth` → `font-size` / `background-color` / `border-bottom-width` |
| 颜色值 | `3022366`（整数）→ `rgb(255,0,255)`（CSS 字符串）|
| 文本 | `content` → `text` |
| 类型 | `type`（div/span/text）→ `tag`（div/span/p） |

### 3. 对比输出分类

**决策**：差异分为四类，终端和报告文件均按此输出：

| 分类 | 含义 | 行动 |
|------|------|------|
| MISSING | 浏览器有但引擎没导出 | 优先增强引擎属性导出 |
| GEOMETRY | 位置/尺寸偏差 | 修正引擎布局计算 |
| MISMATCH | 两边都有但值不同 | 修正格式/计算差异 |
| STRUCTURE | 元素数量/tag 映射错误 | 对齐元素映射 |

**修改文件**：
- `tools/PxTest/Pipeline/ElementCompareStep.php` — 分类输出 + 汇总统计

### 5. 截图控制权统一收口

**问题**：`Application::handleDumpArgs()` 在 `--dump-layout` 和 `--dump-layout-after-frames` 中私自截图，导致 `MultiFrameStep` 每次调用 exe 产一张 timestamp 截图。32 case × 多次迭代 = 169 张垃圾截图（~10MB）。

**根因**：`framework/Core/Application.php` 中 `handleDumpArgs()` 设计耦合——dump-layout 职责是导出布局 JSON，却附带截图副作用。

**修复方案**：截图只由 `main.php` 中的 `--screenshot=xxx` 路径触发，从 `Application::handleDumpArgs()` 中移除截图代码。

**修改文件**：
- `framework/Core/Application.php` — 移除两处截图耦合代码（-12 行）
- `tools/PxTest/Pipeline/Strategy/DumpStrategy.php` — 去掉 `--no-screenshot`
- `tools/PxTest/Pipeline/MultiFrameStep.php` — 去掉刚加的 `--no-screenshot`

**截图控制链**（修复后）：
```
--skip-screenshot → ScreenshotStep 不加入 pipeline，0 张
无 --skip-screenshot → ScreenshotStep 每个 case 用 --screenshot=xxx 产 2 张
其他所有步骤（dump_layout/multiframe/browser_ref）不产截图
```

### 7. 引擎 MISSING 属性补全

**问题**：引擎导出的样式属性远少于浏览器（引擎每元素 2-11 个，浏览器 30+）。238 个 MISSING 中部分可通过 LayoutNormalizer 补全。

**修复**：
- `bg=-1`（透明 sentinel）改为输出 `rgba(0,0,0,0)` 而非跳过
- 从引擎节点字段 `w`/`h` 补全 `width`/`height` 到 styles
- 从引擎节点字段 `x`/`y` 补全 `top`/`left` 到 styles
- 从引擎 style 补全 `position`

**效果**：MISSING 238 → 188（-50），MISMATCH 42 → 78（移过来的新差异）

**修改文件**：
- `tools/PxTest/Layout/LayoutNormalizer.php` — `normalizeNode()` 追加节点字段到 styles；`normalizeStyleValue()` 重写 bg 整数→rgb() 转换

### 8. 锚点自定义属性 + 内容子树提取 + 坐标归一化

**问题**：引擎渲染含 app 外壳（85 元素），浏览器仅测试内容（9 元素），按全局索引对比不对齐。锚点靠颜色/尺寸识别，不够确定。

**方案**：
1. 给所有测试 case 的锚点 div 添加 `data-px-anchor="tl"` 和 `data-px-anchor="br"` 属性（64 个 .html/.vue 文件）
2. `dump_layout.js` 导出元素的 `dataset` 对象
3. `ElementCompareStep.findAnchor()` 三保险查找：`data-px-anchor` > background-color > 8x8 尺寸
4. `ElementCompareStep.extractContentSubtree()` 通过回溯锚点找到父容器，截取容器子节点列表，跳过 app 外壳
5. **锚点归一化**：几何 x/y 坐标转为相对锚点的偏移后再对比

**效果**：
```
before                    after
GEOMETRY  34              GEOMETRY  22  ▼
MISMATCH  78              MISMATCH  39  ▼
STRUCTURE  5              STRUCTURE   0  ▼
MISSING  188              MISSING   185  ▼
total    305              total     246
```

**修改文件**：
- `apps/css-test/test_case/case-*/*.html`（32 个） — 锚点加 `data-px-anchor`
- `apps/css-test/test_case/case-*/*.vue`（32 个） — 锚点加 `data-px-anchor`
- `tools/dump_layout.js` — extractElement() 导出 el.dataset
- `tools/PxTest/Pipeline/ElementCompareStep.php` — 新增 `findAnchor()`（三保险）、`extractContentSubtree()`（跳过外壳）、锚点归一化几何对比

### 10. 引擎 CSS 继承属性缺失修复（LayoutNormalizer 默认值补全）

**问题**：引擎的 `serializeRenderNode()` 只导出节点上显式设置的样式。CSS 继承属性（`font-weight`、`opacity`、`text-align` 等）在子节点上无显式设置则不导出，导致 23 个 MISSING。

**修复**：在 `LayoutNormalizer::normalizeNode()` 中补全 CSS 默认值（`font-weight:400`、`font-style:normal`、`text-align:start`、`opacity:1` 等 9 个属性）。

**效果**：MISSING 185 → 162（-23）

**修改文件**：
- `tools/PxTest/Layout/LayoutNormalizer.php` — 追加 CSS 默认值补全逻辑

**引擎层根因**：`framework/Core/Application.php` 中 `serializeRenderNode()` 应在序列化前递归传播 `color`、`fontSize`、`lineHeight` 等继承属性。入口 `dumpLayoutToFile()` 已定位，添加 `propagateInheritedStyles()` 方法即可再消约 60+ MISSING。
