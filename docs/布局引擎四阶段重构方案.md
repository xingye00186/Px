# 布局引擎四阶段重构方案（零兼容）

## 现状

- 共 110 个测试用例（prt-01 ~ prt-110），**当前 15/110 通过**
- Pipeline: `php apps/php-rt-test/test_pipeline.php`（委托 css-test/test_pipeline.php，带 --app=php-rt-test --php-runtime）
- 无需 AOT 编译，直接 PHP Runtime 运行，快速迭代
- 源码快照：`d:\Px\layout\`（114 个文件，重构期间对照参考）

## 核心工作流（每个迭代周期）

```
1. 运行单 case 测试: php apps/php-rt-test/test_pipeline.php --case=prt-XX-xxx --skip-browser
2. 分析 element_compare_report.md / engine_layout.json 对比差异
3. 定位根因（框架 bug / 工具 bug / 渲染限制）
4. 修改对应 framework 文件
5. 重新运行确认修复
6. 更新问题清单 → 提交
```

## 架构来源

| 来源 | 吸收的部分 | 体现 |
|------|-----------|------|
| Blink CSSPrimitiveValue | CSS 值的类型必须在解析时保留，不可逆 | Phase 1: CSSLength($value, $unit) |
| Blink StyleResolver + ComputedStyle | 样式全量预计算后不可变快照 | Phase 2: ComputedStyle 只读对象 |
| Blink ConstraintSpace | 布局输入显式化 | Phase 3: LayoutConstraints 替代 LayoutContext（删除后者） |
| Blink PhysicalFragment | 布局计算输出不可变中间产物，一次回写 | Phase 3: LayoutFragment + applyTo(RenderNode) |
| Flutter RenderObject | 保留可变节点 + layoutDirty 增量更新 | RenderNode 瘦身保留树结构/脏标记/持久状态 |
| Flutter performLayout() | 单方法接口，内部分配子节点 + 定位 | Phase 3: LayoutStrategyInterface::resolve() 不变 |

## 核心原则

**零向后兼容**。旧 API 在新架构不兼容时直接删除，不留包装器/双轨策略：

- `RenderNode::$style` 数组直接删除，不保留读写兼容
- `PercentResolver::resolvePercent()` 直接删除，消费者改用 `CSSLength::resolveInContext()`
- `CssMappings::parseInlineStyle()` 返回 `ComputedStyle` 而非 `array`
- `serializeRenderNode()` 只读 `ComputedStyle`，无 `$node->style` 回退
- 所有 7 个布局策略一次性迁移到 FragmentBuilder，不允许新旧策略共存

## Phase 1: CSSValue 类型层（预计 2-3 天）

目标：CSS 值类型化。删除旧的 int/string 混合体系，CSS 值的类型信息从解析到布局全程保留。

### 新增

**`framework/Rendering/CSSValue.php`** — 值类型基类 + 具体子类。

```
CSSValue (abstract)
├── CSSLength   — 长度: {value, unit('px'|'%'|'em'|'rem'|'vw'|'vh'|'auto'|'content'), isAuto, isPercent}
│       .resolveInContext(containerSize, parentFontSize, ...): int
│       .px(int): self, .percent(float): self, .auto(): self
├── CSSColor    — 颜色: {argb, isTransparent, isCurrentColor}
├── CSSKeyword  — 标识符: {value('flex-start'|'stretch'|'bold'|...)}
├── CSSRect     — 四边值: {top, right, bottom, left 各为 CSSLength}
└── CSSFlex     — flex 简写展开: {grow, shrink, basis(CSSLength)}
```

### 删除（零兼容，不留包装器）

| 方法 | 文件 | 替代 |
|------|------|------|
| `parsePixels()` 返回 int | `CssValueParser.php` | 返回 CSSLength |
| `parseFlexValue()` basis 返回 int | `CssValueParser.php` | `['basis']` 返回 CSSLength |
| `$pctMap` 硬编码表 | `CssMappings.php` | CSSLength 自动携带 isPercent |
| `$relativeUnitMap` 硬编码表 | `CssMappings.php` | CSSLength.unit 自然区分 |
| `parseIdent()` 返回 string | `CssMappings.php` | 返回 CSSKeyword |
| `PercentResolver::resolvePercent()` | `PercentResolver.php` | 直接调用 CSSLength::resolveInContext() |
| `PercentResolver::resolveMinMax()` | `PercentResolver.php` | 参数改为 CSSLength |
| `PercentResolver::resolveVisualW()` | `PercentResolver.php` | 改为 ComputedStyle 派生属性 `visualWidth()` |
| `PercentResolver::resolveVisualH()` | `PercentResolver.php` | 改为 ComputedStyle 派生属性 `visualHeight()` |
| `PercentResolver::resolveLineHeight()` | `PercentResolver.php` | 改为 ComputedStyle 方法 `lineHeight()` |
| `PercentResolver::resolveTextWidth()` | `PercentResolver.php` | 移入 VNodeRenderer 内部（已由 sk_measure_text_width 替代） |
| `PercentResolver` 整个类 | `PercentResolver.php` | **全部解散，无残留** |

## Phase 2: ComputedStyle + StyleResolver（预计 3-4 天）

目标：独立的样式计算阶段，消除 `$resolvedStyle` 中间层吞值。RenderNode.$style 直接删除。

### 新增

**`framework/Rendering/ComputedStyle.php`** — 不可变样式快照。

- 构造时全量计算：展开简写 → 级联继承 → 填充默认值 → 冻结
- 所有属性以 CSSValue 类型存储（width 是 CSSLength，backgroundColor 是 CSSColor）
- 包含全部约 60 个 CSS 属性
- **不含伪类/伪元素样式**（`:hover`, `:focus`, `::before`, `::after` 是渲染关注点，转移到 RenderNode 的新字段）

```php
class ComputedStyle {
    public readonly CSSLength $width, $height, $flexBasis;
    public readonly CSSColor $backgroundColor, $color;
    public readonly CSSKeyword $display, $position;
    public readonly CSSFlex $flex;
    public readonly CSSRect $padding, $margin, $borderWidth;

    public function __construct(array $declarations) {
        // 1. ShorthandExpander::expandAll($declarations)
        // 2. Cascade + Inherit（ComputedStyle::INHERITED_KEYS）
        // 3. CSS default value fill
        // 4. Freeze（拒绝后续修改）
    }

    public function get(string $key): ?CSSValue;  // 唯一取值通道
    public function toExportArray(): array;         // 供 serializeRenderNode 导出
}
```

```php
class RenderNode {

    public array $pseudoStyles = [];
}
```

## Phase 3: LayoutFragment + 全策略一次性迁移（预计 5-7 天）

目标：消除两阶段布局覆写不可追踪的问题。所有 7 个布局策略一次性切换到 FragmentBuilder，无新旧共存期。

### 新增

**`framework/Rendering/Layout/LayoutConstraints.php`** — 布局约束（输入），**替代 LayoutContext**。合并后者 `$parentX/$parentY` 后删除 LayoutContext。

```php
class LayoutConstraints {
    public readonly int $containerWidth, $contentWidth;
    public readonly int $containerHeight, $contentHeight;
    public readonly int $parentContentX, $parentContentY;  // 来自旧 LayoutContext
    public readonly int $paddingTop, $paddingRight, $paddingBottom, $paddingLeft;
    public readonly int $borderTop, $borderRight, $borderBottom, $borderLeft;

    public function forChild(ComputedStyle $childStyle): self;
    public function withContentWidth(int $w): self;
}
```

所有策略签名从 `(RenderNode, LayoutContext, array $style)` 改为 `(RenderNode, LayoutConstraints, ComputedStyle, FragmentBuilder)`。

**`framework/Rendering/Layout/LayoutFragment.php`** — 不可变布局结果（输出）。对标 Blink PhysicalFragment。

```php
class LayoutFragment {
    public readonly int $x, $y, $w, $h, $visualW, $visualH, $layer;
    public readonly int $contentWidth, $contentHeight;  // scroll container
    public readonly array $children;  // LayoutFragment[]
    public readonly ?ComputedStyle $style;

    /** 原子回写 RenderNode。RenderNode.x/y/w/h 的唯一写入通道。 */
    public function applyTo(RenderNode $node): void;

    /** 对子 fragment 按主轴排序/偏移（flex justify-content / grid placement） */
    public function mapChildren(callable $fn): LayoutFragment;
}

/**
 * FragmentBuilder — 布局计算过程中的可变构建器。
 * build() 后冻结为 LayoutFragment。
 */
class FragmentBuilder {
    private bool $built = false;
    private array $data = [];

    public function setPosition(int $x, int $y): self;
    public function setSize(int $w, int $h, ComputedStyle $style): self;
    public function setLayer(int $layer): self;
    public function setContentSize(int $cw, int $ch): self;
    public function addChild(LayoutFragment $child): self;

    public function build(?ComputedStyle $style): LayoutFragment {
        assert(!$this->built, 'Fragment already built');
        $this->built = true;
        return new LayoutFragment(..., $style);
    }
}
```

### 修改

| 文件 | 改动量 | 关键变更 |
|------|--------|---------|
| `RenderNode.php` | 小 | 移除坐标零散 setter |
| `LayoutStrategyInterface.php` | 不变 | **不改协议**，仍为单 resolve() |
| `LayoutResolver.php` | 中 | resolve() 返回 LayoutFragment；递归子节点 fragment 加入父 builder |
| `BlockLayoutStrategy.php` | **大** | 改为用 FragmentBuilder 构建不可变输出 |
| `FlexLayoutStrategy.php` | **大** | 同上 |
| `GridLayoutStrategy.php` | **大** | 同上 |
| `InlineLayoutStrategy.php` | 中 | 同上 |
| `TableLayoutStrategy.php` | 中 | 同上 |
| `MultiColumnLayoutStrategy.php` | 中 | 同上 |
| `AbsolutePositioning.php` | 小 | 同上 |
| `RenderTreeManager.php` | 中 | VNode→RenderNode 后 resolve()→fragment→applyTo() |
| `VNodeRenderer.php` | 不变 | 仍从 RenderNode 读 x/y/w/h（applyTo 已写入） |
| `Application.php` | 小 | dumpLayoutToFile() 改从 RenderNode 读取即可 |

### 布局流程（新）

```
LayoutResolver.resolve(node, constraints):
  1. strategy = selectStrategy(display, position)
  2. builder = new FragmentBuilder()
  3. for each child:
       childFragment = resolve(child, constraints.forChild(childStyle))
       builder.addChild(childFragment)
  4. strategy->resolve(node, constraints, style, builder)
     策略内部调用 builder.setSize/setPosition 进行纯计算
  5. fragment = builder.build(style)
  6. fragment.applyTo(node)
  7. return fragment
```

### 时序问题（prt-13）解决原理

```
旧时序:
  父 resolveNormalFlow(递归子 → 子 auto-stack 用容器 y=72 ❌)
  → 父 auto-stack(调整容器 y，但子内部 auto-stack 已跑完)

新时序:
  父 resolve(递归子):
    子 resolve:
      子 builder.setPosition(x=309, y=118)  ← 纯计算，不回写
      子 builder.build() → 子 fragment（暂存）
    父读取子 fragment.x/y/w/h（已确定的不可变值）
    父 builder.setPosition(修正) + addChild(fragment)
  父 builder.build() → 父 fragment
  fragment.applyTo(父 RenderNode)  ← 一次性递归回写
    └─ 递归 applyTo: 子 fragment → 子 RenderNode

auto-stack 用到的「容器的 y」来自 LayoutConstraints，
不依赖容器 RenderNode.y（此时 y 仍是旧值但无人读它）。
```

### 删除

| 方法/行为 | 文件 | 理由 |
|-----------|------|------|
| 所有 LayoutStrategy 对 RenderNode.x/y/w/h 的直接写入 | 全部 7 个策略 | 改为 FragmentBuilder.setPosition/setSize |
| `LayoutResolver::resolve()` 返回 void | `LayoutResolver.php` | 改为返回 LayoutFragment |
| `updateFromVNode()` 中旧的两阶段布局调用 | `RenderTreeManager.php` | 改为 resolve() → fragment→applyTo() |
| `ScrollHelper::shiftDescendantsY/X` | `ScrollHelper.php` | Fragment 回写已包含精确坐标，不再需要增量位移；**整个 ScrollHelper 删除** |
| `LayoutContext` 类 | `LayoutContext.php` | 被 LayoutConstraints 完全替代 |

## 技术债务解决状态

| 问题 | 级别 | 方案 | 状态 |
|------|------|------|------|
| CSS 值类型缺失（flex-basis:30% vs 30px） | CRITICAL | Phase 1: CSSLength 保留 unit | 解决 |

每 Phase 完成后 `git tag refactor-phase{1,2,3}-done`。Phase 3 风险最高，应在 tag 前做全量回归。

## RenderNode 最终职责

```
Phase 1 后: 移除 $style → 新增 $computedStyle
Phase 2 后: 样式读写全走 ComputedStyle
Phase 3 后: 坐标统由 fragment.applyTo() 写入

最终 RenderNode（瘦身）:
  ├── 树结构: $type, $key, $parent, $children, $sourceVNode, $groupId
  ├── 布局结果(由 fragment.applyTo 写入): $x, $y, $w, $h, $visualW, $visualH, $layer
  ├── 样式快照: $computedStyle
  ├── 脏标记: $layoutDirty, $lastPaintFrame
  ├── 持久状态: $scrollTop, $contentHeight, $contentWidth
  ├── 交互状态: $hovered, $focused
  └── 渲染缓存: $textRenderInfo
```
