这是一个关于 PHP 编译成原生 EXE 的故事。 .vue 文件 → SFC 编译器 → PHP 代码 → Swoole Compiler → C++ → MSVC → .exe， 一套疯狂但可行的链路，在 17 天内从零长成了一个五脏俱全的桌面 GUI 框架。

下面按 git 时间线 展开，每一个节点都是真实的 commit。

🌱 第一章 · 创世纪 2026-05-24

故事的起点平凡到不值一提：一个叫做 VueCalc 的破计算器。

2026 年 5 月 24 日，第一条 commit 诞生了：1c24171。没有 GitHub 仓库，没有设计文档，只有一个念头——用 PHP 写桌面 GUI，然后编译成 exe。

这是原型机时代的全部家当：

  • 一个计算器：数字按钮 + 运算符 + 显示屏，GDI 硬画
  • Win32 消息循环：while($running) { PeekMessage; if(dirty) render(); usleep(16000); }
  • 脏标记模型：每次 state 变化设 $this->dirty = true，下一帧重绘全局
  • GDI 双缓冲：CreateCompatibleDC → 离屏绘制 → BitBlt 一次刷新
  • 布局？硬编码！$x = 10; $y = 80; $w = 60; $h = 50 手写到每个按钮
💡闪光点：#1 AOT 的「禁术」发现

早期代码大量使用 __get / __set 魔术方法来做响应式绑定。直到撞上 Swoole Compiler AOT 的墙——AOT 不支持魔术方法。这迫使框架转向显式的 dirty 标记 + 手动 setter/getter。回头看，这个限制反而让代码路径变得清晰可追踪，是一种「被迫的正确」。

⚙️ 第三章 · 编译器时代 2026-05-27

框架活了，但生产力是零——写一个按钮要手写 VNode::h() 调 4 次，填 x/y/w/h，还要自己管 dirty。这不行。

🔥 第八章 · AOT native_types 的烈焰试炼 2026-06-02

这是框架经历的最严峻的考验——Swoole Compiler v1054 引入 use native_types 编译指令。

native_types 将 PHP 的类型化属性直接编译为 C++ 原生类型（int → int32_t，string → std::string），性能飞跃但兼容性地狱。

从 commit 5139bc2（注入 use native_types 编译指令）开始，一连串 AOT 兼容性修复排山倒海而来：

  • 闭包类型声明改造（0d7b305）
  • 平台事件和 VNode 添加 use native_types（c38b8d0）
  • C2440 类型转换修复——php::Var → php::Int 的显式转型（6ec9473）
  • 跨文件 native_types_chain 连锁检查（a319bbc）
  • AOT/PHP CLI 双模式兼容的 getBindValue()（28a6234）
  • 跨文件属性访问的 getter 方法（f990628）
💡闪光点：#7 C2440 与 native_types_chain

AOT 编译的经典错误 C2440: 'initializing': cannot convert from 'php::Var' to 'int'。根因是 native_types 下跨文件读到的属性类型是 php::Var（未标记 native_types 的编译单元），而非原生 int。解决方案是 native_types_chain——从依赖树的叶子节点向上，逐文件确保链路上每个类都被标记。这是 AOT 框架特有的「类型传染病」问题。

🎨 第九章 · Skia 降临与后端革命 2026-06-03 ~ 06-04

GDI 能做的事情有限——圆角矩形靠 AlphaBlend 拼凑，阴影靠模糊预处理，透明靠 BitBlt 奇技淫巧。是时候请外援了。

💡闪光点：#8 降级不是失败，是设计

大多数框架在渲染后端选择上采用「要么全有要么全无」的策略。Px 的设计是渐进降级——Skia D3D11 崩了？退到 Skia CPU。Skia 加载失败？GDI 永远 standby。用户不会看到黑屏，只可能看到「渲染质量降低」的提示。这套设计来自 commit 196d3d3，后来被经验文档记录为「降级不是失败，是设计」。

💡最后的闪光：#11 LayoutContext 封装——一个值对象的诞生

布局计算的上下文曾经是 6 个松散变量在函数间传递。commit eedff10 把它们封装成 LayoutContext 值对象——parentX、parentY、parent、scrollOffset 等全部打包。看似简单，但这让布局策略函数的签名从 resolveNode($node, $px, $py, $scroll, ...) 变成了 resolveNode($node, $ctx)——扩展性天差地别。有趣的是，LayoutContext::$parentX 初始化为 0 这个细节本身就是一个「血的教训」——在 native_types 下，未初始化的 int 属性是 null，null + int 就是 TypeError。
